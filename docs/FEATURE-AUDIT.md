### Improvements to existing Orbit code before expanding scope

- **Clipboard responsiveness:** Orbit reads `NSPasteboard` synchronously in its main-actor tick. Vorssaint's [history service](https://github.com/vorssaint/vorssaint-utils/blob/4244163b464cbbdedb6158b1d2ffc281e1688205/Sources/Vorssaint/Services/Clipboard/ClipboardHistoryService.swift) uses a serialized off-main lane with timeouts because providers can stall. Introduce bounded reads before adding images and persistent history. This is a code-path risk identified by inspection, not a reproduced Orbit freeze.
- **Volume-slider response:** Orbit sends `Float(app.level.volume)` directly to the audio route. Merged [#3052](https://github.com/vorssaint/vorssaint-utils/pull/3052) maps the range below unity to a curve and keeps boost linear. Its final patch includes migrating old saved gains to new slider positions, despite the earlier PR description saying stored apps would become quieter. Preserve perceived output on migration in Orbit too.
- **Headset behaviour:** Merged [#2969](https://github.com/vorssaint/vorssaint-utils/pull/2969) offers a preferred headset on connection and can mute speakers after disconnect. Orbit has saved per-app routes but not these connection policies. Respect subsequent manual changes and exercise actual headset hardware; upstream did not validate connect switching on hardware in that PR.
- **Feature lifecycle:** The upstream [FeatureRuntime](https://github.com/vorssaint/vorssaint-utils/blob/4244163b464cbbdedb6158b1d2ffc281e1688205/Sources/Vorssaint/App/FeatureRuntime.swift) starts services only for enabled modules and stops them when disabled. Orbit has individual toggles but no comparable full module lifecycle. Establish this before adding capture, download watchers and other background readers.
- **Bounded caches:** Open [#3096](https://github.com/vorssaint/vorssaint-utils/pull/3096) reduces thumbnail/window-preview budgets. Orbit does not have those caches yet; take the lesson—explicit memory budgets and visible-item decoding—when adding image history, rather than copying numerical limits without measurement.

### Boundaries and recommended order

1. Improve clipboard threading and audio response; investigate the MX Master 4 event shape without changing the user's mapping.
2. Build rich clipboard and the file shelf together, then connect downloads and the existing conversion tools.
3. Add calendar/meeting controls and an optional overview that preserves the current remembered-page behaviour.
4. Extend agent attention alerts, fresh usage readings and Keep Awake integration.
5. Add OCR, wheel profiles, Pomodoro and richer notes as individually switchable modules. Prototype voice typing separately.

These local workflows can be designed with **£0 recurring hosting/API cost**; engineering and compatibility maintenance remain the real work. Calendar/screen/microphone access are contextual permissions, not purchases. Provider monitoring uses the user's existing sign-in; it does not include free model inference. Do not add a paid LLM or hosted backend for these features.

Broader Now Playing support is useful, but the reviewed [adapter](https://github.com/vorssaint/vorssaint-utils/blob/4244163b464cbbdedb6158b1d2ffc281e1688205/Sources/NowPlayingAdapter/NowPlayingAdapter.swift) uses private MediaRemote access through a helper loaded by a platform Perl process. Orbit currently uses Music/Spotify automation. Treat universal browser playback as a separate compatibility prototype, not an equally straightforward API addition. App cleanup, fan control, a full recorder/editor, menu-bar organization and cloud sharing would substantially widen the product and its maintenance requirements.

Vorssaint labels its code [GPL-3.0-or-later](https://github.com/vorssaint/vorssaint-utils/blob/4244163b464cbbdedb6158b1d2ffc281e1688205/LICENSE); Orbit currently carries an MIT licence. The plan here is to implement the useful behaviours in Orbit's own code and design, not import the upstream implementation or branding wholesale.

## Integration contracts

- **Codex:** [official app-server account and rate-limit methods](https://learn.chatgpt.com/docs/app-server#authentication). Rate-limit reads are separate from sign-in failures; unavailable values stay unavailable. Each bucket retains its own window and reset time. No inference, credit purchase or reset consumption is initiated.
- **Claude:** [official status-line JSON](https://code.claude.com/docs/en/statusline#available-data). Connect metrics wraps an existing command and forwards the same JSON to it, preserving its terminal output and other status-line options. Disconnect restores the original object only if the installed object is still owned by Orbit. Edits made afterward are not overwritten. The metrics file keeps display fields only.
- **Activity:** [Codex hooks](https://learn.chatgpt.com/docs/hooks) and [Claude hooks](https://code.claude.com/docs/en/hooks). Child start/stop events use separate IDs and cannot mark the parent complete. Repair refreshes Orbit's bridge and its exact handlers, preserving unrelated hooks. Provider restart/trust requirements still apply.

The app distinguishes account connection, installed handlers, current bridge, and actual event arrival. None of those alone proves every session or provider surface is observable. Local-only Work/Codex sessions may emit supported hooks; cloud orchestration has different support. No transcript or credential-file scraping is used as a fallback.

### Sound mixer — 8 October 2026

Compared [Vorssaint's mixer](https://github.com/vorssaint/vorssaint-utils/blob/b0599423cbf38dd0e28415ccd3f9874a2548668f/Sources/Vorssaint/UI/Notch/NotchMixerView.swift) and its public audio behaviour at revision `b0599423cbf38dd0e28415ccd3f9874a2548668f`. Orbit independently implements the direct-adjustment workflow: no separate Enable mixer button; editing a level, muting or selecting an app output creates only the route needed. Returning to 100% and System output releases it. Favourites, order, levels and output UIDs persist; disconnected selected outputs temporarily use the system output and retain the preference for reconnection.

Core Audio process taps feed private aggregates without installing a driver. App setup runs away from the UI thread, stale builds are discarded, working routes survive a failed replacement where possible, and a route with no valid render callbacks is released. Output shape changes rebuild the route. The renderer handles Float32 stereo/mono/planar output, ignores physical microphone input buffers, clears unwritten frames and limits boosted peaks. Unsupported formats show an unapplied state instead of a successful-looking control. Mixing requires macOS 14.4; ordinary device controls remain available on macOS 14.

The compact horizontal mixer is shared by the notch, wheel and menu bar. The continuous app list scrolls independently of the fixed device controls; all Orbit scroll areas suppress scrollbar indicators. App-icon menus offer pinning, ordering, output selection, reset and retry. Typed percentages complement native accessible horizontal sliders; active apps have a small status dot. Options include app mixing on/off, inactive visibility, microphone visibility/input, sound-effects output and reset. Broader device automation and dedicated wireless-streaming features remain outside this pass. There are no new dependencies or running costs.
